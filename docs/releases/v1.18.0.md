# Policy Core Module Release v1.18.0

Welcome to the latest release of `Policy` module of [SIGHUP Distribution](https://github.com/sighupio/distribution) maintained by team SIGHUP by ReeVo.

This is a minor release including the following changes:

- Add support for Kubernetes 1.36
- Update Gatekeeper to version 3.23.1
- Update Kyverno to version 1.19.1
- Update Gatekeeper Policy Manager to version 2.1.0

## Compatibility

This release adds support for Kubernetes 1.36.x while maintaining compatibility with versions 1.33.x through 1.35.x.

> [!NOTE]
> Kyverno's upstream documentation declares support for Kubernetes v1.33 to v1.35 for the v1.19 line.
> We validate Kyverno v1.19.1 against Kubernetes 1.36 in our own end-to-end test suite, and Kyverno
> v1.19 added support for `MutatingAdmissionPolicy` v1 on Kubernetes 1.36, but be aware that running
> it on 1.36 is ahead of upstream's declared support range.

## Notable changes

### Gatekeeper

Mutation resources (`Assign`, `AssignImage`, `ModifySet`) gained an optional `operations` field on
`spec.applyTo`, which restricts the admission operations that trigger the mutation. Leaving it unset
preserves the previous behaviour, so existing mutation policies are unaffected.

### Kyverno

Kyverno v1.19 introduces the `policies.kyverno.io` API group alongside the existing `kyverno.io` one,
adding the `ValidatingPolicy`, `MutatingPolicy`, `GeneratingPolicy`, `ImageValidatingPolicy` and
`DeletingPolicy` types together with their namespaced variants. The default policies shipped by this
module continue to use `kyverno.io/v1` `ClusterPolicy`, which remains the stored version.

The admission and background controllers gained the `--excludeBootstrapResources` and
`--maxGlobalContextEntries` flags, both set to their upstream defaults.

### Gatekeeper Policy Manager

GPM moves from `v1.1.1` to `v2.1.0`, crossing the `v2.0.0` major release. **The module's own
deployment is unaffected**: it runs GPM with no `GPM_*` environment variables, no mounted kubeconfig
and no authentication, and none of the `v2.0.0` breaking changes apply to that shape.

If you have customised the GPM deployment, review the
[`v2.0.0` release notes](https://github.com/sighupio/gatekeeper-policy-manager/releases/tag/v2.0.0)
before upgrading. In particular: the `/api/v1/*` JSON API was removed, the in-container kubeconfig
path moved to `/home/nonroot/.kube/config`, GPM refuses to start when `GPM_AUTH_ENABLED=OIDC` and
`GPM_SECRET_KEY` is left at the published 1.x default or is shorter than 16 characters, and the log
level now accepts only `DEBUG`, `INFO`, `WARN` and `ERROR`.

This release also sync the package's RBAC, which was missing read access to
`mutations.gatekeeper.sh` and to core `events`.

`v2.1.0` itself adds a Resources view grouping audit violations by namespace and object, optional
RBAC-aligned filtering, and support for running behind an authenticating proxy with
`GPM_AUTH_ENABLED=JWT`. None of these are enabled by default here.

Two user-visible details if you link to GPM directly: the configuration view moved from `/configs` to
`/configurations`, and constraint anchors changed from `#<name>` to `#<Kind>--<name>`.

## Update Guide 🦮

### Process

#### Gatekeeper

To upgrade this package from `v1.17.0` to `v1.18.0`, you need to download this new version, then apply the `kustomize` project. No further action is required.

This also upgrades Gatekeeper Policy Manager to `v2.1.0` and widens its `ClusterRole`, since both ship
inside the same `kustomize` project.

```bash
kustomize build katalog/gatekeeper | kubectl apply -f -
```

#### Kyverno

To upgrade this package from `v1.17.0` to `v1.18.0`, you need to download this new version, then apply the `kustomize` project. No further action is required.

The Kyverno CRDs are updated in place: no stored API version changes in this release, so no resource
migration is needed and existing `ClusterPolicy` objects are preserved.

```bash
kustomize build katalog/kyverno | kubectl apply -f -
```
